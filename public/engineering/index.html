Designing a public boundary.

A working example of how an independent professional website can capture opportunities without turning a private operating environment into a public directory.

The problem

Public portfolios need a useful and credible way to present work. A visitor should not need an account to explore the public experience, and the contact workflow should not provide access to other visitors' information.

The implementation

A responsive public site serves a deliberately authored set of pages. A POST-only inquiry endpoint validates input and uses a separate server-side connection to store a structured request. Project case studies are built from a dedicated publication manifest rather than an operational inventory.

What has been verified

The November 27, 2026 V2 release passed ten automated source and build checks, including publication schema, private-data boundaries, metadata, inquiry validation and sitemap generation. The production home page and sitemap responded successfully in deployment checks, and the inquiry endpoint refused GET requests. These checks demonstrate specific behavior, not a guarantee against every possible vulnerability.

Where this is useful

The design is relevant to founder portfolios, independent venture studios and teams that need to turn incoming conversations into structured records while separating public information from private operating data.
