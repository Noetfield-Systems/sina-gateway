# SINA Gateway V2
Public professional identity; never an operational-system mirror. No external inventory ingestion. The curated public manifest starts empty; only explicitly Founder-approved, evidence-backed and sanitized case studies may be added. Maintain candidate assessments and operational data in a separate private system, not this public repository. Never commit private names, screenshots, credentials or candidate scoring data. The approval reference should be an opaque non-secret receipt. Weights: credibility 20, technology 20, design 15, business 15, innovation 10, founder fit 10, evidence 10. Ratings 0–100. Approval is mandatory independently of score. Only six top approved case studies render. Case fields: problem, solution, marketOpportunity, technology, capabilities, architecture, verifiedMilestones, screenshots, stage, founderContribution, collaboration. Screenshots require approved local assets. No implied venture ownership.
## Build
npm install; npm test; npm run build. Vercel serves public/ and the POST-only inquiry function. Configure GATEWAY_DATABASE_URL as sensitive server-only variable. Inquiry table in dedicated database includes status and next_action_at. No public inquiry reading endpoint. Review privately with authorized DB access.
## Release checks
Verify root, unknown paths and legacy URLs anonymously, inspect sitemap and public assets, POST synthetic inquiry and confirm DB row, reject GET/invalid POST, review mobile and desktop. Past deployment URLs, caches and search-index removal need separate verification; never assume removal of an old alias removes immutable deployments.
